## 反模式判定

**综合结论：低风险。** 此页面不像是 AI 生成的界面。它具有明确的设计体系、有目的的组件组合和 Material 3 模式的一致性。未发现典型的 AI 特征（渐变文字、毛玻璃默认、Hero-metric 模板、同质卡片网格）。

## 总体印象

设置页面整体结构清晰，5 个分组的 `_SettingsSection` 模式合理，间距体系基本遵循设计规范。但细节处理上多处背离了"克制"和"统一"品牌关键词：**媒体来源卡片信息过载** 是最严重的问题——超过 200 行的复杂控件、段落式技术文档级别的描述，与"精致·轻盈"的设计理念明显冲突。退出登录无确认对话框是另一个高风险点——一次误触即可丢失整个会话。

---

## 做得好的地方

1. **主题预览颜色小圆点**（行 146-170）：用 10×10 的带阴影色块直观预览每个主题模式，是克制而有品位的细节设计。

2. **桌面端 Hover 反馈**（`_HoverableListTile`，行 564-611）：160ms 的 `AnimatedContainer` 提供柔和的背景过渡，遵循了"轻柔不抢戏"的动画原则。

3. **BlocBuilder buildWhen 优化**：三个 BlocBuilder 都使用 `buildWhen` 精确过滤状态变更，避免不必要的重建，代码性能意识良好。

## 优先级问题

### P0: 退出登录无确认对话框

- **问题**：行 56，`onTap: context.read<AuthCubit>().logout` 直接调用，无 `showDialog` 包装
- **为什么重要**：退出登录是破坏性、不可逆的操作。一次误触导致会话立即丢失。用户可能因此丢失未保存的播放队列
- **修复**：包裹确认对话框，提供"取消"和"退出"两个选项。同时添加该区域应有的"当前账户信息"（用户名、服务器 URL）
- **建议命令**: `/impeccable harden`

### P1: 媒体来源卡片信息过载，违背"克制"品牌关键词

- **问题**：`_CustomMediaSourcesCard`（行 288-411）包含段落级描述（如"适合接入封面代理、图床转发或统一压缩服务。若地址里没有模板变量……"）、URL 输入框、测试按钮、状态胶囊、测试结果横幅 — 全部同时可见
- **为什么重要**：这直接违背品牌关键词"克制"。描述读起来像是 API 文档而非用户界面文案。目标用户是"对审美有追求的自托管音乐爱好者"，不应该在设置面板中阅读模板变量替换的细节
- **修复**：将详细技术描述移到工具提示（`Tooltip` 或 `Info` 图标按钮）。行内描述缩短到一行。考虑渐进式展示：默认只显示开关和当前状态摘要，展开后才显示 URL 输入和测试控件
- **建议命令**: `/impeccable distill` + `/impeccable clarify`

### P1: 设计规范与实现不一致 — 缺少账户信息和缓存清理

- **问题**：设计规范 11.5 节要求"存储"区域应包括下载管理入口 + **缓存清理**，"连接与账户"应包括**当前账户信息** + 退出登录。两者都缺失
- **为什么重要**：设计规范是"唯一设计参考"，实现未对齐导致用户功能缺口
- **修复**：存储卡片中添加缓存清理行（可清除音频缓存 + 图片缓存）。退出登录上方显示当前账户信息（服务器 URL、用户名）
- **建议命令**: `/impeccable harden`

### P2: 硬编码间距值违背 4px 网格体系

- **问题**：多处间距使用非 4px 倍数的值（6, 10, 14, 18px），设计规范 4.1 节要求"以 4px 为最小单元，所有间距为其整数倍"
- **具体位置**：
  - `EdgeInsets.all(18)` — 行 352，自定义媒体来源卡片内边距
  - `SizedBox(height: 6)` — 行 360 和 668
  - `SizedBox(width: 14)` — 行 481
  - `width: 10, height: 10` — 行 158-159 主题预览点
  - `SizedBox(width: 10)` — 行 655 测试横幅
  - `SizedBox(height: 18)` — 行 367
  - `SizedBox(height: 14)` — 行 516
- **为什么重要**：违背 4px 网格使页面在视觉上出现"微差"——用户可能不明显但专业眼会注意到。网格一致性是"精致"品牌承诺的技术基础
- **修复**：将所有间距值对齐到 4 的倍数（4, 8, 12, 16, 20, 24...），优先引用 `AppSpacingTokens`
- **建议命令**: `/impeccable polish`

### P2: 状态胶囊颜色层级倒置

- **问题**：行 454-456，`_SourceSection` 的状态胶囊使用了反转的颜色权重：
  - 自定义来源**启用时**：`tertiaryContainer` 在 **78% 透明度**
  - 自定义来源**禁用时**：`surfaceContainerHighest` 在 **100% 不透明度**
- **为什么重要**：禁用（非活跃）状态比启用（活跃）状态具有更高的视觉权重，颜色层级完全倒置。在深色模式下 `surfaceContainerHighest` (#212A3B) 比 78% 透明度的 `tertiaryContainer` 更具视觉侵略性
- **修复**：倒置透明度——活跃状态用 100% 不透明度，非活跃状态降低透明度或使用更浅颜色
- **建议命令**: `/impeccable colorize`

### P2: 零无障碍标注

- **问题**：整个文件 684 行中，零个 `Semantics` 组件、零个 `semanticLabel`、零个 `Tooltip`
- **为什么重要**：设计规范 14.1 节要求"所有交互元素需有 Semantics 标签"。屏幕阅读器用户完全无法访问此设置页面
- **修复**：在所有交互元素上添加 `Semantics` 标签。Radio、Switch、ListTile 都需要标注
- **建议命令**: `/impeccable audit`

### P3: Radio 组缺少选中态视觉容器

- **问题**：主题选择 Radio 组（行 101-131）使用纯 Column 布局，选中项没有高亮背景（相比之下 `_HoverableListTile` 有 hover 反馈）
- **为什么重要**：当前选中的主题行无法一眼识别。设计原则"识别而非回忆"要求当前选中项在视觉上显眼
- **修复**：对选中 Radio 行应用 `primaryContainer` 背景色，匹配设计规范中 FilterPill 选中态模式
- **建议命令**: `/impeccable polish`

### P3: 状态胶囊重复 MetaPill 组件

- **问题**：`_SourceSection` 手动构建的状态胶囊（行 502-514）使用 Container + 自定义样式。设计规范 8.2 节定义了 `MetaPill` 组件，已完成组件化
- **为什么重要**：重复实现导致组件体系不统一，增加了维护成本。自定义实现的内边距(`horizontal: 12, vertical: 8`)与规范(`horizontal 10-12, vertical 6-7`)有偏差
- **修复**：替换为共享的 `MetaPill` 组件，如需自定义颜色则扩展其 API
- **建议命令**: `/impeccable polish`

### P3: 僵尸代码残留

- **问题**：行 145 `// Phase 4: Theme preview color dot`，行 563 `// Phase 4: ListTile with hover background change`
- **为什么重要**：阶段/迭代标记表明工作按阶段进行，代码已实现但注释未清理。给后续维护者造成困惑
- **修复**：删除两处 `// Phase 4:` 注释

### P3: 卡片嵌套模式不一致

- **问题**：5 个分组使用 3 种不同的卡片嵌套模式。前 3 个（外观、播放、媒体来源）使用专用的 `_XxxCard` 组件包裹 Card，后 2 个（存储、连接与账户）在 body 层直接写入 `_SettingsSection > Card > _HoverableListTile`
- **为什么重要**：不同的嵌套模式意味着卡片样式定义在两个位置，增加了不一致的风险
- **修复**：将后两个分组提取为 `_StorageCard`、`_AccountCard`，使 5 个分组统一使用 `_SettingsSection(child: _XxxCard())` 模式

## 次要观察

1. **Hover 动画时长偏差**：`_HoverableListTile` 使用 160ms，设计规范要求 180ms（"状态切换"），`AppMotion` 已有 `micro(150ms)` 和 `short(220ms)` 但就是没有 180ms。建议统一到规范值 180ms
2. **42×42 图标容器**（行 473-474）：不遵循 4px 网格（应为 40 或 44）
3. **`_SourceSection` 行中 Switch 无换行保护**：在极窄屏幕上可能导致内容溢出
4. **`initState` 读取 cubit state 的竞态条件**（行 303-308）：异步加载时可能读到空值
5. **设计规范 spacing 数值已过时**：规范写 `sectionGap = 18`、`sectionTitleBottomGap = 12`，实际 `AppSpacingTokens` 已是 24 和 16——代码正确但需要更新规范文档

## 值得思考的问题

1. **"媒体来源"区域是否应该从主设置页移出？** 它占据最大的视觉体积和认知负荷，却是最少数用户会触碰的设置。作为"高级"子页面屏蔽掉，主设置页保持核心 4 项设置是否更好？
2. **退出登录的体验终点是什么？** 当前零摩擦退出传达了"不关心你是否离开"。增加一个温柔的告别触摸（如简短过渡动画或提示"已安全退出"）是否会让体验更有人性？这符合还是违背"克制"原则？
3. **当设置页的媒体来源说明文字比 Apple Music 整个设置页还长时，目标用户定义是否清晰？** 自托管音乐爱好者有技术能力，但他们对审美同样有要求——技术文档 vs 精致 UI 的边界在哪里？
