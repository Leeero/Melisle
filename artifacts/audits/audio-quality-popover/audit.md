# 设置页音质 Popover 审查

## 审查范围

- 步骤 1：桌面设置页打开“在线音质”选择菜单。
- 用户目标：快速理解各档位差异，确认当前选项，并用鼠标或键盘完成切换。
- 证据：`01-quality-popover-open.png`、当前 Flutter 实现、`docs/design-macos-v4.md` 与 `docs/design.md`。

## 总体结论

当前方案可完成选择，锚点位置、点击目标和当前值回显基本成立；但选中态、信息解释和键盘可达性仍不足。优先修复键盘操作与语义，其次收紧视觉层级和选项表达。

## 发现

1. **高优先级：触发行不可可靠地通过键盘聚焦和打开。** `_HoverableListTile` 使用 `GestureDetector`，没有显式 Focus/Actions/Semantics 按钮语义；这与 V4 的键盘优先要求冲突。
2. **中优先级：选中态只依赖绿色图标和勾选。** 当前项没有整行选中底色或 radio 语义，快速扫读和辅助技术识别都偏弱。
3. **中优先级：档位含义不够透明。** 桌面菜单省略了移动 Bottom Sheet 已有的描述；“自动”尤其容易被理解为动态按网络调节，而领域定义实际是透传源文件、不转码。
4. **中优先级：五个相同 HQ 图标重复且信息价值低。** 它们增加视觉噪声，却不能帮助区分自动、无损与码率档位。
5. **低优先级：浮层偏重。** 高表面色、10 级 elevation 和较大的纵向体量让菜单像独立卡片，遮盖后续设置内容；与 V4 的弱阴影、安静层级不完全一致。
6. **一致性风险：当前绿色 active 色属于旧 V3 语言。** V4 最高优先级规范使用潮汐蓝 active/Brand wash；若设置页已进入 V4 迁移范围，Popover 也应随共享主题统一迁移，而不是局部硬改。

## 建议顺序

1. 将触发行改为可聚焦、可用 Enter/Space 打开的按钮语义；确认方向键、Enter、Esc 和焦点返回。
2. 当前项使用轻量 Brand wash + check/radio 语义，hover 与 selected 分离。
3. 移除重复 HQ 图标，改为短标签配一行必要说明；明确“自动＝原始音质/不转码”或重命名。
4. 将菜单阴影降到 V4 的轻提升层，并让菜单更贴近右侧当前值触发区。

## 证据限制

- 截图只能确认静态视觉状态，不能确认 hover、focus、动画、键盘和读屏行为。
- 当前 shell 没有 `flutter` 命令，未能重新执行现有 widget tests。
