# Melisle V3 迭代重构方案

## 1. 方案结论

当前项目已经具备 V3 所需的大部分真实业务能力，适合进入渐进式 UI 重构，但不适合进行一次性页面重写。

重构应遵循以下顺序：

1. 先恢复可判断回归的绿色测试基线。
2. 固化 V3 设计系统、响应式规则和共享交互原语。
3. 先改 App Shell、登录和通用状态，再迁移内容页面。
4. 播放器、队列、下载等高状态密度模块放在共享能力稳定后处理。
5. 每个页面按垂直切片迁移，保留现有 Repository、Cubit 和真实后端数据链路。

建议以 8 周、4 个双周迭代执行；若只有一名开发者，按 10～12 周执行，不压缩验收环节。

## 2. 审查基线

### 2.1 V3 设计稿基线

本方案以 Stitch 项目 `Melisle 乐岛 Unified V3` 的最新内容为依据。当前设计范围已经延伸到 V3-56。

重复编号或同一页面存在多个版本时，采用以下优先级：

1. 带“重塑版”“完善版”“更新版”的画板优先于同编号旧稿。
2. V3-46～V3-56 的规范稿高于早期页面中的局部表现。
3. V3-01 中文设计系统与项目 `design.md` 共同构成视觉事实源。
4. 设计稿与真实协议能力冲突时，以 `MusicRepository` 和 Emby/Subsonic 实现能力为边界。

### 2.2 当前代码基线

当前已经实现：

- Emby、Navidrome/Subsonic 自动探测与登录、会话恢复。
- 首页、搜索、媒体库、专辑/艺术家/歌单详情、收藏、历史。
- 播放、队列、播放模式、音质、歌词、睡眠定时器。
- 离线下载、下载目录、设置持久化、自定义歌词和封面来源。
- Android、iOS、macOS、Windows 以及桌面托盘和快捷键。

### 2.3 当前质量基线

2026-08-06 执行完整测试：109 个用例执行，7 个失败。已确认的失败覆盖：

- 移动 MiniPlayer 的队列按钮触控目标实际为 40px，规范要求至少 44px。
- 下载页响应式 smoke test 失败。
- 媒体库移动加载态文案/结构与测试契约不一致。
- 桌面曲目表稳定行操作无法定位。
- 桌面播放器布局契约失败。
- 桌面歌单详情返回入口契约失败。

静态分析有 3 条警告：一个未使用方法、两个从未传入的 `isPrimary` 参数。

因此阶段 0 完成前，不允许开始大范围页面替换。

## 4. 明确不纳入本轮重构的功能

以下内容不能因为设计稿中出现图标或入口就直接实现：

- Cast/投屏：当前领域契约、播放器和协议适配层均无投屏能力。
- 独立 DNS/服务器管理中心：当前产品是单入口自动探测，不存在多服务器管理领域模型。
- 会员、Pro、订阅、支付：项目没有商业化能力或授权模型。
- WebDAV/NAS 正式接入：当前仅有未接入启动流程的仓库骨架。
- 播放列表新建、编辑、删除：当前 `MusicRepository` 只有读取接口。
- 社交、评论、推荐算法、云同步：当前协议和本地模型均不支持。

设计稿中的对应装饰或入口应删除、隐藏，或明确标注为未来能力，不应做不可用按钮。

## 5. 目标代码结构

保持现有 Clean Architecture，不改动依赖方向：

```text
presentation/
├── pages/                 # 页面组装、路由参数、页面级 Provider
├── blocs/                 # 页面/业务状态，不承载视觉 token
└── widgets/
    ├── controls/          # 按钮、Tab、弹层、反馈、输入
    ├── feedback/          # loading、empty、error、skeleton
    ├── layout/            # App Shell、Page Scaffold、Toolbar、Detail Hero
    ├── media/             # artwork、album/artist/playlist card
    ├── playback/          # MiniPlayer、播放控制、进度、队列视图
    └── tracks/            # 移动曲目行、桌面曲目表、曲目操作
```

约束：

- 页面文件只负责组合和页面级差异，目标建议控制在 700 行以内。
- 共享组件必须通过参数表达差异，不读取特定页面 Cubit。
- Cubit 不依赖 BuildContext、Theme 或断点。
- 桌面与移动共享数据状态，只分离视图组件，不建立两套业务状态源。
- 不为“复用”创建万能配置对象；只有两个以上真实消费者且语义一致时才抽象。

## 6. 重构节奏

### 日常节奏

每个垂直切片按 5 天节奏推进：

1. 第 1 天：冻结页面基准、列出状态矩阵、补契约测试。
2. 第 2～3 天：实现共享组件和页面迁移。
3. 第 4 天：桌面/移动视觉比对、键盘与无障碍验证、修复回归。
4. 第 5 天：完整相关测试、静态分析、真实后端 smoke、合并和记录差异。

每个 PR 只包含一个共享基础能力或一个功能域，建议控制在 800 行有效变更以内；播放器拆分可以按组件分多个 PR。

### 迭代节奏

| 阶段 | 建议时间 | 目标 | 是否允许发布 |
| --- | ---: | --- | --- |
| 0. 基线稳定 | 3～5 天 | 现有测试恢复绿色，冻结 V3 基准 | 否 |
| 1. 设计基础设施 | 1 周 | token、断点、页面框架、状态组件、弹层原语统一 | 内部预览 |
| 2. 壳层与登录 | 1 周 | App Shell、导航、MiniPlayer 外壳、登录完整迁移 | Alpha |
| 3. 内容发现 | 2 周 | 首页、搜索、媒体库、收藏、历史 | Alpha/Beta |
| 4. 详情与播放 | 2 周 | 详情页、曲目操作、播放器、队列、歌词 | Beta |
| 5. 下载与设置 | 1 周 | 下载、设置、自定义媒体源 | RC |
| 6. 全局收口 | 1 周 | 深色主题、可访问性、性能、跨平台回归 | 正式发布候选 |

## 7. 分阶段实施与验收

### 阶段 0：恢复绿色基线

实施：

- 修复 7 个现有测试失败，先判断是实现回归还是旧测试契约过期。
- 统一 MiniPlayer 和紧凑按钮的视觉尺寸与 44px 语义触控尺寸。
- 修复下载页在目标宽度的布局异常。
- 明确媒体库 loading 状态的唯一文案和语义标签。
- 恢复曲目表操作、播放器桌面布局和详情返回入口的稳定测试标识。
- 清理 3 条静态分析警告。
- 记录 375、768、1080、1440 四个宽度的基线截图。

验收门禁：

- `flutter test` 100% 通过。
- `flutter analyze` 0 warning、0 error。
- Android/iOS 逻辑尺寸 375 宽无 overflow。
- macOS/Windows 1080 和 1440 宽无 overflow。
- 现有 Emby 与 Navidrome 登录、播放、切歌、搜索、下载各完成一次 smoke。

### 阶段 1：设计基础设施与共享原语

实施：

- 冻结 `AppColorTokens`、`AppSpacingTokens`、`AppRadiusTokens`、`AppMotion`。
- 统一四档断点，不允许页面自行定义宽度阈值。
- 将 `page_layout.dart` 按 Page Scaffold、Header、State View、Detail Hero 拆分。
- 建立统一的 `AppLoadingView`、`AppEmptyView`、`AppErrorView`、分页 footer。
- 统一 `AppModal`、移动 Sheet、桌面侧面板、Snackbar 和确认操作。
- 建立字体缩放、长文本、焦点、Semantics 的组件级测试夹具。

验收门禁：

- 共享组件 golden/结构测试覆盖浅色与深色、紧凑与桌面布局。
- 所有可交互控件触控/点击目标不小于 44px。
- 1.0、1.3 字体缩放下无关键内容截断。
- 页面不得新增硬编码品牌色和私有断点。
- 现有业务 Cubit 和 Repository 行为测试不变。

### 阶段 2：App Shell、导航、MiniPlayer 与登录

实施：

- 依据 V3-46 重构桌面 Sidebar、中等图标栏和移动五 Tab。
- 统一顶部工具栏、返回行为、内容滚动区域和底部避让。
- MiniPlayer 只保留一个状态到 UI 的映射层，覆盖无曲目、加载、播放、暂停、缓冲、失败、不可播放。
- 登录页拆为响应式框架、品牌区、登录表单和连接状态组件。
- 登录仍采用自动探测 Emby/Subsonic，不增加协议选择造成第二事实源。

验收门禁：

- 未登录只能进入 `/login`，已登录访问 `/login` 自动回 `/home`。
- 五个移动 Tab、桌面全部导航项和浏览器式返回行为正确。
- MiniPlayer 在所有主页面的位置、尺寸和状态一致。
- 输入中按空格不会触发播放快捷键。
- 登录默认、校验、连接中、失败、成功跳转状态有 widget test。
- macOS/Windows 窗口缩放跨越断点时不丢失当前路由和播放状态。

### 阶段 3：内容发现与集合页面

实施：

- 首页按区块拆分：最近播放、最新添加、常听、随机探索。
- 搜索拆分为 Search Input、Recent Search、Scope Tabs、Result Sections 和完整状态视图。
- 媒体库按歌曲、专辑、艺术家、歌单拆成独立视图，共用一个 LibraryCubit 状态源。
- 抽象曲目集合页模板，供歌曲列表、收藏、历史复用。
- 统一 V3-42 分页、加载更多、部分失败和重试策略。

验收门禁：

- 每个页面验证 loading、success、empty、error、partial error、load more 六类适用状态。
- 搜索去抖、提交、清空、历史撤销和类型筛选有自动化测试。
- 媒体库切 Tab 不重复创建业务状态，不出现旧请求覆盖新筛选结果。
- Emby 与 Navidrome 各验证歌曲、专辑、艺术家、歌单数量和分页终止行为。
- 375/768/1080/1440 宽截图与 V3 基准逐页比对。
- 大列表滚动无明显掉帧，构建和图片加载不阻塞主交互。

### 阶段 4：详情页、曲目操作、播放器、队列与歌词

实施：

- 统一专辑、艺术家、歌单的 Detail Hero、元信息和操作区。
- 统一移动曲目行与桌面曲目表，曲目操作只从一个 action model 生成。
- 将 `player_page.dart` 拆为 desktop/mobile layout、artwork、lyrics、timeline、core controls、secondary controls、overlay。
- 保留 `PlayerCubit` 和音频内核行为；只有测试证明必要时才调整状态模型。
- 桌面队列使用右侧面板，移动队列使用 Sheet，共享队列列表和编辑动作。
- 歌词覆盖加载、无歌词、同步、偏移、用户滚动、回到当前和错误状态。

验收门禁：

- 播放、暂停、上一首、下一首、拖动进度、音量、四种播放模式行为回归通过。
- 队列重排、删除、清空、播放指定项均有 Cubit 与 widget 测试。
- 页面切换、窗口变宽和打开浮层不会重建或中断播放器。
- 系统媒体控制、锁屏/通知控制与 App 内状态一致。
- 歌词点击跳转、偏移和回到当前行为有确定性测试。
- 所有播放按钮、Slider、当前曲目和当前歌词具备可读屏语义。
- 连续播放 30 分钟进行桌面和移动真机/模拟器 smoke，无队列漂移和明显内存增长。

### 阶段 5：下载、设置与自定义媒体源

实施：

- 下载页拆分任务区、已下载区、存储设置和删除确认。
- 下载状态明确区分等待、下载中、暂停/取消、失败、完成、文件缺失。
- 设置页采用数据驱动的分组描述，但保存行为仍由现有 Cubit 明确处理。
- 统一主题、音质、曲间间隔等选择器的移动 Sheet 和桌面 Dialog。
- 自定义媒体源只覆盖歌词/封面解析配置，不冒充 WebDAV 音乐后端。

验收门禁：

- 下载队列、取消、删除、失败重试、本地优先播放测试通过。
- 下载目录变更在支持与不支持平台都有明确反馈。
- 设置修改后重启应用仍能恢复，非法值有边界校验。
- 退出登录、清理缓存、删除下载均有二次确认和结果反馈。
- Emby/Navidrome 在线音质选择产生正确请求或流地址。

### 阶段 6：全局一致性与发布收口

实施：

- 按 V3-50 全页面检查深色主题，不接受局部反色或硬编码白色表面。
- 按 V3-52 检查桌面键盘导航、焦点顺序和快捷键冲突。
- 按 V3-56 检查对比度、触控目标、读屏、字体缩放和长文本。
- 删除迁移后废弃组件、重复 token、临时 feature flag 和过期测试。
- 完成 Android、iOS、macOS、Windows 打包和真实设备检查。

验收门禁：

- `flutter test` 和 `flutter analyze` 全绿。
- 所有路由完成浅色/深色、375/768/1080/1440 矩阵检查。
- 中文界面无英文残留；专有名词 Emby、Navidrome、Subsonic 除外。
- 200% 长标题、长艺术家名和空封面数据不溢出。
- 键盘可到达所有桌面核心操作，焦点环清晰可见。
- 四个平台至少完成一次 release 构建；核心流程 smoke 清单全部通过。

- 写出 loading、empty、error、success、disabled、pending 状态矩阵。
- 确认不修改无关 Repository/协议行为。

### 视觉与交互

- 浅色、深色两套主题。
- 字体缩放 1.0、1.3。
