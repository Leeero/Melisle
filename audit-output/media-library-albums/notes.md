# 媒体库／专辑页审查

## 2026-09-01 修订结果

- 桌面端补充“专辑”标题、已显示数量、专辑搜索和封面尺寸切换。
- 网格改为依据内容区真实宽度计算列数，不再使用包含侧栏的窗口总宽度。
- 采用明确的 `mainAxisExtent` 预留标题与元数据空间，1.3 倍文字缩放测试无溢出。
- 支持“大封面 / 紧凑网格”两种真实布局密度。
- 专辑卡片从仅封面可点击改为整卡可点击，并保留键盘焦点、语义标签和稳定悬停反馈。
- 缺失封面统一为低饱和单色占位，降低对真实封面的视觉竞争。

定向 Widget 测试、桌面工具栏烟雾测试与静态分析均已通过。

## 截图步骤

1. 打开媒体库并进入“专辑”子页面 — 状态：需修复。

## 观察到的优点

- 左侧导航、顶部搜索、底部播放器与当前浅色主题的表面层级一致。
- 选中态使用品牌绿，专辑卡片的 12px 圆角与项目设计令牌一致。
- 封面、标题、元数据的阅读顺序直接，单张专辑有可访问的语义标签。

## 主要问题

1. 第二行最右侧卡片出现 `BOTTOM OVERFLOWED BY 0.222 PIXELS`。这是产品界面可见的渲染错误，会破坏完成度，也说明固定网格高度未充分覆盖字号／行高的浮点计算。
2. 多数缺失封面共用同一种“彩色渐变 + 波形”视觉语言，整页像占位内容；色彩同时在竞争注意力，真实封面（第三张）反而缺少层级优势。
3. 仅在侧栏显示“专辑”选中，内容区没有页面标题、专辑数量、排序或筛选入口。大库存下难以确认当前位置和控制浏览结果。
4. 长标题和元数据都被省略，但没有截图可见的悬停提示或备用阅读路径；乱码／问号文本被原样展示，降低可读性与信任感。
5. 7 列大封面在本桌面宽度下占据了首屏大部分面积；连续浏览时，用户需在每张卡片之间反复扫视标题与元数据，信息密度偏低。

## 可访问性风险与验证缺口

- 仅凭截图无法确认键盘焦点、Tab 顺序、缩放和屏幕阅读器表现。
- 溢出在系统字体放大或不同平台字形下可能更严重；应在文字缩放和窄宽度下验证。
- 淡色封面与白色波形的局部对比度取决于色板，不能仅从截图认定满足对比度要求。
